# Pre-registration — instrument-collapse governance (H1) and harness attribution (H3)

**Committed before the treatment arms were run.** The git history is the timestamp: this file lands
in a commit that precedes any commit containing the factorial results. If a later commit changes an
analysis choice recorded here, that change is a deviation and is logged in §8, not edited away.

The reason for the formality is specific rather than ceremonial. Two of the results this project
already produced were artifacts that looked like findings (§0), and the literature this work sits in
is currently being told that its harness comparisons are unfalsifiable for want of budget matching
and held-out regimes (arXiv:2607.12227). Writing the analysis down first is the cheapest available
defence against both.

---

## 0. What has already been measured (and is therefore NOT a prediction)

Recorded for honesty about what was known when the predictions below were fixed.

| Fact | Value | How |
|---|---|---|
| Headroom, epidemic instrument-collapse regime | **1.70×** | `scripts/recalibrate.py --seeds 20` |
| Headroom, scalar state-shock regime | **1.13×** | same |
| Headroom, every *state*-dynamics shock family tried | 1.00–1.26× | `scripts/severity_sweep.py`, `scripts/headroom_audit.py` |
| Frozen (pre-shock optimal) policy | `0.9 if I > 0.01 else 0.0` | calibration artifact |
| Oracle (post-shock optimal) policy | `0.9 if I > 0.25 else 0.0` | calibration artifact |
| Pilot, 2 seeds, `outcome+memory`, gemini-3.5-flash-lite | post_loss 11.47 / 13.04 vs frozen 19.02 / 21.04 | pilot run |

The pilot is the reason the predictions below are directional rather than open. It used 2 seeds and
one model, so it is a reason to expect an effect, not evidence of one; it is disclosed because a
"prediction" made after seeing a pilot is a weaker thing than one made blind, and readers should be
able to discount accordingly.

## 1. Claims

**H1 (adaptation).** On the epidemic instrument-collapse regime, a code-as-policy regent with a
performance-feedback harness attains lower post-shock governance loss than the calibrated frozen
institution.

**H1b (rival).** The same regent attains lower post-shock loss than budget-matched trace-less OPRO.

**H3 (attribution).** The reduction is carried by the **outcome-feedback** channel. Specifically:
the main effect of `outcome` is negative and survives Holm correction; the main effect of `trace` is
not distinguishable from zero.

**H4 (negative control).** On the scalar regime (headroom 1.13×) no arm's improvement over frozen
survives correction.

## 2. Primary metric

`post_loss` = infection burden + λ·intervention cost over steps ≥ 100, λ = 0.08, horizon 200.
Lower is better. Emitted by `EpidemicLoss.components`. **One primary metric, fixed in advance.**
`total_infected`, `peak_infected`, `post_cost` are secondary and reported without inferential claims.

Normalized regret `R = (arm − oracle) / (frozen − oracle)` is a rescaling of the primary metric, not
a second test. It is computed per seed against the paired anchors before averaging.

## 3. Design

- **Seeds**: 0–19 (n = 20), identical across every arm. Paired throughout.
- **World**: `govsim/domains/scalar/regimes.py::EPIDEMIC_SHOCKED`, pinned. Shock at t = 100 sets
  `lockdown_efficacy` 1.0 → 0.25; transmissibility unchanged, so the break is purely instrumental.
- **Anchors**: generated by `scripts/recalibrate.py` into `docs_gates/calibration.json`, by
  exhaustive search over a shared policy family. Frozen = optimal on the stationary pre-shock world;
  oracle = optimal on the post-shock window of the shocked world.
- **Factorial**: full 2³ over `{trace, outcome, memory}`, all eight cells, registered
  programmatically so no cell can drift in its seeds or horizon.
- **Budget**: every LLM arm decides on `EveryN(10)` ⇒ 20 model calls per run. The critic arm is
  **not** budget-matched and is reported separately, labelled.
- **Models**: primary `gemma-4-31b-it` (full factorial). Replication panel on the reduced arm set
  {bare, outcome, all-three}: `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`. Temperature 0 for
  the regent, 0.8 for OPRO's proposal step (OPRO requires proposal diversity to function).

## 4. Analysis

- Paired per-seed differences; percentile bootstrap, 10 000 resamples, 95% CI, RNG seed 0.
- "X beats Y" **requires the CI to exclude 0**. n ≥ 2 enforced (a single shared seed yields a
  zero-width interval that trivially "excludes" 0).
- Factorial effects: ±1 contrast coding, contrasts formed **within** each seed before aggregation.
- **Correction**: Holm across the family of 7 factorial terms; Holm across the family of named
  contrasts. α = 0.05.
- Collapsed/terminated runs are counted worst-case, never dropped.

## 5. Falsification

| Claim | Falsified by |
|---|---|
| H1 | CI of (best harnessed arm − frozen) on `post_loss` includes 0 at n = 20 |
| H1b | CI of (best harnessed arm − OPRO) includes 0 |
| H3 | `outcome` main effect does not survive Holm, **or** `trace` does |
| H4 | a scalar-regime arm beats frozen after correction (would mean headroom understates what is achievable outside the calibration family) |

## 6. Known threats, and what is done about each

- **The oracle is only optimal within its family.** A code-emitting regent is not confined to it, so
  beating the oracle would be a statement about the family, not about adaptation. Mitigation: the
  oracle is re-calibrated over a *union* of families (threshold, proportional, threshold-with-floor,
  the last two added after the pilot showed the regent emitting `0.5 * I`), and R is reported against
  both the narrow and widened references.
- **Interaction effects.** Single-component ablation is known to mislead when scaffold components
  interact. Mitigation: full factorial with interaction terms estimated, not assumed zero.
- **Budget confound.** Mitigation: matched call counts; actual counts reported per arm.
- **Prompt-hint confound.** No arm's prompt names the shock, the efficacy parameter, or a solution
  structure. The obfuscated-prompt template was already stripped of solution coaching for this
  reason (see `decisions.md`).
- **Model non-determinism.** Every call is recorded to a content-addressed tape; reported runs
  replay byte-for-byte without a key.
- **Free-tier model selection.** The panel is what was reachable without paid inference. This biases
  toward smaller models and is disclosed rather than corrected.

## 7. What would make us abandon rather than adjust

If the epidemic regime's headroom fails to reproduce at n = 20 with a widened oracle family — i.e.
if the widened oracle closes most of the frozen→oracle gap — then the regime does not support the
question and the H1 result is withdrawn rather than re-tuned into existence. Severity is not a free
parameter to be adjusted until a result appears; that is the failure this whole apparatus exists to
prevent.

## 8. Deviation log

*(append-only; each entry gives the date, what changed, and why)*

- **2026-08-04** — initial registration.

- **2026-08-04 (same day, after the first control arm returned) — PRIMARY METRIC CHANGED from
  `post_loss` to full-horizon `loss`; a new reference `best_fixed` becomes the falsification target.**

  *What triggered it.* The **no-harness control** arm returned `post_loss` 12.73 (gemini-3.5-flash-lite)
  and 13.58 (gemini-3.1-flash-lite) against frozen 20.11 and the post-window oracle 11.84 — i.e.
  R ≈ 0.11 for an arm that receives no feedback of any kind. The policy audit explained it: that arm
  emits **64% bare constants**, never referencing the state at all.

  *The flaw.* A post-break-only metric rewards passivity. A policy that never intervenes is wrong
  before the break and, precisely because the break disables the instrument, nearly right after it.
  It scores well on the post-window metric without having adapted to anything. The metric could not
  distinguish "adapted" from "did nothing, and doing nothing happened to be right afterwards" —
  which is the entire question.

  *The fix.* Score the **full horizon**, and add the **best fixed law in hindsight** (`best_fixed`)
  as the non-adaptive ceiling. No fixed law can be optimal on both sides of a break that moves the
  optimum, so beating `best_fixed` requires genuinely changing behaviour and cannot be reached by
  passivity. `switching` (pre-break optimum → post-break optimum at the exact break) becomes the R=0
  anchor. Re-calibrated at n=20: frozen 27.97, best_fixed 27.11, switching 23.74 ⇒ adaptation is
  worth **1.142×** over the best fixed rule. The scalar negative control drops to **1.039×**, so the
  diagnostic still separates the two regimes.

  *Why this is a deviation and not a repair of a typo.* It changes the headline number and it was
  made after seeing a treatment-adjacent result, so it is disclosed in full. Nothing about the
  worlds, seeds, arms, harness components, or correction procedure changed; the LLM call tape is
  unaffected (no prompt depends on the scoring window), so every arm is re-scored on the identical
  recorded runs rather than re-sampled. **H1/H1b/H3/H4 above are to be read against full-horizon
  `loss` with `best_fixed` as the named non-adaptive rival.**

- **2026-08-04 — REFERENCE FAMILY WIDENED to span both instruments.**

  *The flaw.* The reference policies were calibrated over lockdown only, while every treatment arm
  can set lockdown **and** vaccination. That does not make the reference a weaker opponent, it makes
  it an unfair one: an arm would beat it partly by using an instrument the reference was forbidden.

  *Why it matters substantively, not just formally.* Calibrated jointly, the pre-break optimum uses
  **no** vaccination and the post-break optimum uses the **maximum**. So the correct response to the
  instrument failure is *substitution* toward the instrument that still works — a far better
  governance task than the withdrawal the single-lever calibration implied, and it removes the
  degeneracy where the clairvoyant answer was close to "do nothing".

  *The fix.* `PolicyFamily` gained `extra_laws`, and all three reference vocabularies (threshold,
  proportional, threshold-with-floor) now carry a standing vaccination term. Re-calibrated at n=20.
  This is the limitation the paper had already flagged as future work; it is now in the design.

- **2026-08-04 — FIRST FACTORIAL RUN DISCARDED: output-token truncation, correlated with the treatment.**

  *What was found.* The outcome-feedback arm emitted **no parseable action on 32.5%** of its
  decisions (`epidemic_llm_trace_outcome`: 22.5%); the no-harness and memory arms: **0%**. A decision
  that emits nothing leaves the *previous* law installed, so those arms were not the treatments they
  were labelled as — they were partly "sticky policy".

  *Cause.* `gemma-4-31b-it` reasons inside a `<thought>` block before calling the tool. At
  `max_tokens=1500` it exhausted the budget mid-reasoning. Measured directly on the same prompt:
  1500 ⇒ 0/4 tool calls (truncated at 1827 total tokens); 3000 ⇒ 4/4 (2715 tokens).

  *Why it is disqualifying rather than noisy.* The failure is **correlated with the treatment**. A
  harness channel lengthens the prompt and invites longer deliberation, so the arms carrying more
  information truncate more. An ablation run this way measures truncation and reports it as
  information — in the direction that manufactures a null.

  *Action.* The entire factorial is re-run at `max_tokens=4000` into `logs/runs_gemma4k`. The
  discarded run is retained in `logs/runs_gemma` and is **not** reported. `analyze_matrix.py` now
  runs a no-action-rate gate *before* the factorial and refuses to let the tables be read past a
  >2% rate.

  *An accidental finding kept from the discarded run.* `trace_outcome` truncated **less** than
  `outcome` (22.5% vs 32.5%). When a decision produces nothing the Runner records an error,
  `TraceFeedback` surfaces it on the next turn, and the model acts. So `TraceFeedback` is **not** the
  pure null this pre-registration predicted — it is a recovery channel for exactly this failure mode.
  H3's prediction that "trace does nothing here" is therefore **wrong as stated**, and is corrected
  to: *trace does nothing when the regent is emitting well-formed policy, and is load-bearing when
  it is not.*

- **2026-08-04 — SEVERITY AND PRICE WERE CONFOUNDED; now varied one at a time.**
  The `epidemic_severe` cell set λ=0.15 *and* drove efficacy to 0, so its result (large staleness,
  zero adaptation headroom) could not be attributed to severity. λ is now held at the flagship's
  0.08 there, and a separate `epidemic_pricey` cell varies only the price. Both still show ≈1.00
  adaptation headroom (severe 1.007, pricey 1.000), so the qualitative finding survives — and is now
  stronger, because it holds along *each* axis separately. Reported in full rather than silently
  re-run.

- **2026-08-04 — MODEL PANEL REDUCED by the provider's daily quota.**
  The free tier turned out to allow **500 requests per model per day**, and one arm costs 400 calls
  (20 seeds × 20 reviews). Only the `gemma` family has enough headroom for the full 2³ factorial. The
  panel is therefore: `gemma-4-31b-it` (full factorial), `gemma-4-26b-a4b-it` (reduced arm set), and
  `gemini-3.5-flash-lite` / `gemini-3.1-flash-lite` contributing the no-harness arm only before
  exhausting their quota. Reported as a partial replication, and as a constraint on inference rather
  than a design choice.
