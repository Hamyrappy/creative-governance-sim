Краткое описание системы (для понимания поведения)
- Состояние состоит из главной компоненты `x_main` (это то, что у нас в данных называется `current_x`) и двух связанных вспомогательных факторов `x_aux1`, `x_aux2`.  
- Динамика линейная и стохастическая: каждая координата на следующем шаге — это линейная комбинация текущих состояний + управление + сдвиг + шум. Главная компонента получает «подтягивания» от `x_aux1/x_aux2`, а они — от `current_x`.  
- Управление применяется не сразу: ты задаёшь команду `u_cmd`, но на систему действует сглаженное значение `u_eff = rho_u * current_u + (1 - rho_u) * u_cmd`,  
  поэтому резкие команды не дают мгновенного эффекта — учитывай лаг.  
- Параметры могут медленно дрейфовать, а во вспомогательные факторы периодически приходят «толчки» (шоки). Любая политика должна быть устойчивой и адаптивной.

> Важная оговорка: для генерации выражения управления тебе недоступны структурные параметры связей (например, `a12`, `a13`, `a21`, `a31`, `gamma1`, `gamma2`) и имя `x_main`. В выражениях ты работаешь только с белым списком имён (см. ниже). При этом ты видишь историю последних шагов и текущие значения ключевых метрик.

Жёсткие ограничения на выражение политики
- Возвращай только один JSON-объект внутри ```json-блока (см. формат ниже). Никакого текста вне блока.
- `"policy_type_id"` должен быть `"set_control_input"`.
- `"value_expression"` — это одно математическое выражение на Python без присваиваний, импортов, вызовов произвольных функций и побочных эффектов.  
  Разрешены: числа, переменные из белого списка, скобки, операции `+ - * /`, функция `abs(...)`.
- Не используй имён вне белого списка (в частности, `x_main`, `a12`, `a13`, `a21`, `a31`, `gamma1`, `gamma2` — запрещены).
- Не делай ручного клиппинга (`min`, `max`, `np.clip` и т.п.). Система сама ограничит результат в `{u_range_min} … {u_range_max}`.
- Учитывай инерцию управления: из-за `rho_u` мгновенной реакции нет; крупные коэффициенты могут вызвать перерегулирование.
- Стремись снижать MSE с умеренным MSU — избегай чрезмерных по модулю коэффициентов.

Рекомендации по дизайну выражения (не копируй дословно)

Цель — робастное демпфирование ошибки и колебаний с учётом лага управления:
- База: пропорциональный компонент к ошибке `current_x - target_x`.
- Демпфер по инерции: штраф на `current_u` и/или на `previous_x`.
- Если используешь `x_aux1/x_aux2`, делай их вклад малым по модулю.

- `-1.0*(current_x - target_x) - 0.25*previous_x - 0.15*current_u`
